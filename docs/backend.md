# Бэкенд: Telegram Stars + таблица рейтинга

Один **Cloudflare Worker + D1** (worker/). Клиент общается с ним из [js/net.js](../js/net.js); пока адрес воркера не вписан в `BACKEND_URL`, магазин и рейтинг в игре не показываются — игра работает полностью локально, как раньше.

**Развёрнутый инстанс:** https://transport-manager-backend.nikamoniava166.workers.dev (аккаунт nikamoniava166@gmail.com, база D1 `transport-manager`, строгий режим оплат включён).

## Что делает воркер

| Endpoint | Метод | Назначение |
|---|---|---|
| `/health` | GET | Проверка, что воркер жив |
| `/products` | GET | Список товаров и цены (⭐) |
| `/save` | POST | Прогресс игрока (капитал/уровень/рейсы) → таблица рейтинга; вместе с ней — резервная копия полного сейва (таблица `saves`) |
| `/restore` | POST | Резервная копия сейва: последняя версия или `null` |
| `/grant` | POST | Бонусы игроку от владельца: отдаёт и сразу помечает выданными |
| `/refer` | POST | Рефералка: новый игрок докладывает «меня пригласил ref<id>» (одна запись на игрока) |
| `/refclaim` | POST | Рефералка: счёт неоплаченных приглашений (клиент начисляет награду) + помечает их выданными; возвращает и общее число приглашённых |

### Бонус игроку

Владелец игры может подарить игроку деньги одной командой из папки `worker` (игрок получит их при следующем запуске или разворачивании приложения, с тостом и записью в журнал операций):

```
wrangler d1 execute transport-manager --remote --command "INSERT INTO grants (user_id, kind, amount, note, created_at) VALUES (<telegram_id>, 'money', 300000, 'Бонус от владельца игры', <мс-метка времени>)"
```

Выдача одноразовая: `/grant` помечает строку `claimed_at` в момент отдачи. Пока поддерживается `kind='money'`.

### Штраф игроку

Тот же механизм, но с отрицательной суммой — клиент списывает деньги и пишет запись «расход» в журнал операций (баланс не уводится в минус: если денег меньше штрафа, списывается всё до нуля):

```
wrangler d1 execute transport-manager --remote --command "INSERT INTO grants (user_id, kind, amount, note, created_at) VALUES (<telegram_id>, 'money', -150000, 'Штраф за название компании', <мс-метка времени>)"
```

Важно: сначала убедись, что на сайте опубликован клиент с поддержкой отрицательных грантов (коммит «Balance: owner fines via grants»), иначе воркер пометит грант выданным, а старый клиент его проигнорирует и штраф пропадёт.

### Реферальная программа

Приглашённые хранятся в таблице `referrals` D1 (referee — уникальный, самоприглашение исключено на сервере). Механика целиком клиент-серверная, без ручных команд:

1. Игрок в «Ещё» → «Пригласить друзей» жмёт «Поделиться ссылкой»: открывается стандартное окно Telegram со ссылкой `https://t.me/RussianTruckManager_bot/RussianTruckManager?startapp=ref<telegram_id>`.
2. Друг открывает игру по ссылке — клиент читает `start_param`, разово начисляет новичку `refBonusNew` (50 000 ₽) и при первом `/refer` фиксирует пару в D1.
3. При запуске и каждом разворачивании приложения клиент вызывает `/refclaim`: воркер отдаёт число ещё не оплаченных приглашений и помечает их выданными; клиент начисляет пригласившему `refBonusInvite` (30 000 ₽) за каждого с тостом и записью в журнал операций.

Числа задаются в `js/data.js` (`refBonusNew`, `refBonusInvite`, `refLink`, `refShareText`) — на сервере сумм нет. Ссылка собирается в `Game.net.shareInvite` ([js/net.js](../js/net.js)), логика — в `Game.init` ([js/app.js](../js/app.js)).
| `/leaderboard` | POST | Топ-20 по капиталу + место игрока |
| `/purchase` | POST | Создать счёт Telegram Stars (`createInvoiceLink`) |
| `/purchase/claim` | POST | Активировать оплаченный счёт (один раз); в строгом режиме немного ждёт подтверждения вебхуком |
| `/purchase/pending` | POST | Оплаченные, но не активированные счета — клиент добирает их при запуске |
| `/tg-webhook` | POST | Вебхук бота: помечает счёт оплаченным |

Авторизация клиентских запросов — по подписи `Telegram.WebApp.initData` (HMAC-SHA256 с токеном бота, подпись старше 24 часов отвергается). Имя в рейтинге берётся из Telegram-профиля.

## Развёртывание (однократно, ~15 минут)

1. **Аккаунт Cloudflare** (бесплатного тарифа достаточно): [dash.cloudflare.com](https://dash.cloudflare.com), регистрация по почте.

2. **wrangler** (CLI Cloudflare) — нужен Node.js:
   ```
   npm install -g wrangler
   wrangler login
   ```

3. **База D1** — в папке `worker/`:
   ```
   wrangler d1 create transport-manager
   ```
   Выведенный `database_id` впиши в [worker/wrangler.toml](../worker/wrangler.toml).

4. **Схема**:
   ```
   wrangler d1 execute transport-manager --remote --file=worker/schema.sql
   ```

5. **Токен бота** (из @BotFather) как секрет:
   ```
   wrangler secret put BOT_TOKEN
   ```

6. **Деплой** из папки `worker/`:
   ```
   wrangler deploy
   ```
   Получишь адрес вида `https://transport-manager-backend.<твой-сабдомен>.workers.dev`.

7. **Подключить игру**: впиши адрес в `BACKEND_URL` в [js/net.js](../js/net.js) (первая строка внутри функции) и опубликуй сайт (`git push`).

8. Проверка: открой `https://<адрес>/health` — должен ответить `{"ok":true}`.

### Вебхук оплат (обязателен для покупок)

Без вебхука оплаты не проходят: при нажатии «Оплатить» Telegram присылает боту апдейт `pre_checkout_query`, и воркер должен за 10 секунд ответить `answerPreCheckoutQuery` — молчание отменяет транзакцию (у игрока выглядит как «оплата не прошла»). Статус «paid» воркер ставит из апдейта `message.successful_payment`; он же нужен строгому режиму `STRICT_PAYMENTS`:

1. Придумай случайный `WEBHOOK_SECRET` (любая строка) и задай его:
   ```
   wrangler secret put WEBHOOK_SECRET
   ```
2. Пропиши вебхук боту (вместо `<TOKEN>` и `<адрес>`):
   ```
   curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<адрес>/tg-webhook&secret_token=<WEBHOOK_SECRET>"
   ```
   Параметр `allowed_updates` можно опустить — тогда доставляются все апдейты бота; воркер использует `message` и `pre_checkout_query`, остальное игнорирует.
3. Для строгой проверки оплат раскомментируй в [worker/wrangler.toml](../worker/wrangler.toml):
   ```toml
   [vars]
   STRICT_PAYMENTS = "1"
   ```
   — тогда `/purchase/claim` активирует покупку только после подтверждения вебхуком. Без вебхука и строгого режима активация происходит по колбэку `paid` от клиента (двойная активация одного счёта исключена — статус хранится в D1).

### Возвраты

Stars-платежи можно вернуть через Bot API `refundStarPayment` (user_id + charge_id из обновления `successful_payment`) — при желании добавь вызов в `/tg-webhook`.

## Товары и цены

Задаются в начале [worker/worker.js](../worker/worker.js) (`PRODUCTS`) и дублируются подписями в [js/net.js](../js/net.js) (`DEFAULT_PRODUCTS`) — итоговую цену всегда создаёт воркер.

| Товар | Цена | Эффект (модель «без сильного облегчения») |
|---|---|---|
| 💳 Денежный перевод | 25 ⭐ | +25 000 ₽ × уровень, **раз в сутки** — сопоставимо с несколькими рейсами, не открывает технику |
| ⭐ Удвоенный доход | 50 ⭐ | ×2 к оплате рейсов на 24 ч (продлевается, не стакается мгновенно) |
| 🔧 ТО всего парка | 15 ⭐ | Износ всех машин и прицепов → 0 (удобство: ремонт и так дешёвый) |
| ⏩ Ускорение рейсов | 10 ⭐ | Все активные рейсы приезжают на 15 минут раньше (мгновенный эффект, без кулдауна; в UI заблокировано, когда рейсов нет) |

## Замечания по честности

- Прогресс в рейтинг отправляет клиент — как и весь сейв, игра клиентская. Подпись `initData` гарантирует, что запись делает реальный пользователь Telegram, но не перепроверяет экономику. Для казуальной таблицы этого достаточно; при желании ужесточить — валидируй капитал по истории `invoices`/`trips` в D1.
- Двойная активация покупки невозможна (статус счёта в D1). Поддельный «paid» без реальной оплаты возможен только в мягком режиме до включения `STRICT_PAYMENTS`.
